## 2. Metrics — `analysis/metrics.py`

```python
def eal(losses: np.ndarray) -> float                      # mean
def var(losses: np.ndarray, alpha: float) -> float        # empirical quantile
def cvar(losses: np.ndarray, alpha: float) -> float
def cvar_indices(losses: np.ndarray, alpha: float) -> np.ndarray
def tail_mask(losses: np.ndarray, alpha: float) -> np.ndarray
def bootstrap_ci(losses, stat_fn, n=1000, seed=0) -> tuple[float, float]
```

**CVaR definition (use exactly this, and document it):**
with `n` scenarios and `k = ceil(n * (1 - alpha))`, CVaR is the mean of the `k`
largest losses. For `alpha=0.95, n=1000` → mean of the worst 50.
This is the simple empirical form, not the interpolated Rockafellar–Uryasev
form; it is exact enough here and makes the tests deterministic.

## 3. Criticality — `analysis/criticality.py`

```python
@dataclass(slots=True)
class AssetCriticality:
    asset_id: str
    portfolio: Portfolio
    standalone_loss_ph: float       # only this asset fails, no flood
    annual_failure_prob: float      # fraction of scenarios where damaged
    tail_criticality_ph: float      # CVaR reduction if invulnerable
    eal_criticality_ph: float       # EAL reduction if invulnerable
    systemic_ratio: float           # see below
    served_population: int
    recovery_criticality_h: float   # reduction in system recovery time
    explanation: list[str]          # dependency chain strings for the UI
```

### 3.1 Computation

```
For each asset a:
  1. standalone_loss: engine.simulate(no-flood scenario,
        Overlay(forced_failures=(a,), flood_enabled=False)).weighted_loss_ph
  2. affected = [i for i in scenarios if a in table.damaged[i]]
     annual_failure_prob = len(affected) / n
  3. If affected is empty -> tail_criticality = 0, systemic_ratio = 0.
     Else: re-simulate ONLY `affected` with Overlay(invulnerable=(a,)),
     substitute those losses into a copy of the weighted array,
     tail_criticality = cvar(original) - cvar(modified)
  4. systemic_ratio = tail_criticality / max(epsilon,
        annual_failure_prob * standalone_loss * n_tail_weight)
     where n_tail_weight = (1 - alpha) ** -1 ... see §3.2
```

### 3.2 Systemic ratio — exact definition

```
expected_direct = annual_failure_prob * standalone_loss_ph
systemic_ratio  = tail_criticality_ph / max(expected_direct, 1.0)
```

Interpretation: > 1 means the asset matters more in the tail than its own
expected standalone damage implies — it is systemically important.
Flag `systemic = systemic_ratio > 2.0`.

### 3.3 Explanation strings

For each asset, produce human-readable chains to the top 3 affected zones:

```
"S2 → F4 → TX10 → Z10 (8,400 people, energy)"
"S2 → P2 → K3 → H2 → health access for Z9–Z12 (31,000 people)"
```

Generated by walking `downstream()` restricted to `POWERS`, `SUPPLIES_WATER`,
`BACKHAULS`, then to zones. Cap at 3 chains, longest-population first.

### 3.4 Performance

Naively this is `n_assets × n_affected` simulations. Required optimisations:

- Skip assets with `annual_failure_prob == 0`.
- Cap `affected` at the union of (tail scenarios) ∪ (200 random others);
  document this as an approximation and report the cap in the output.
- Parallelise across assets with `concurrent.futures.ProcessPoolExecutor`
  when `n_jobs > 1`.

Target: full criticality pass over 75 assets × 1000 scenarios in under 5 minutes
single-threaded.

## 4. Hidden single points of failure — `analysis/spof.py`

```python
@dataclass(slots=True)
class Spof:
    kind: Literal["shared_dependency", "colocation", "common_cause", "recovery"]
    shared_asset: str | None
    redundant_group: list[str]      # the assets that looked redundant
    affected_zones: list[str]
    affected_population: int
    service: Service
    design_storm_failure_prob: float
    explanation: str
```

### 4.1 Detectors (implement all four)

**A. Shared dependency**
```
For each zone z and each service with redundancy (COMMS via z.towers;
HEALTH via reachable hospitals; WATER via multiple tanks if present):
  closures = [township.upstream(p) | {p} for p in providers]
  shared   = intersection(closures)
  for each s in shared: emit Spof(kind="shared_dependency", shared_asset=s, ...)
```

**B. Co-location**
```
For each redundant group, collect HOSTED_ON providers of every member
(transitively). Any host appearing for ALL members is a co-location SPOF.
```

**C. Common-cause hazard exposure**
```
Take the 1-in-100-year design storm (highest rain in the train set).
For each redundant group, compute P(all members fail) using the fragility
curves at that storm's depths, assuming independence within the group.
If > 0.25, emit a common_cause SPOF.
```

**D. Recovery SPOF**
```
For each asset a, compute the set of road edges that appear in EVERY shortest
path from any matching depot to a. If that set is non-empty, those edges (and
their host assets) are recovery SPOFs for a.
Implement by: for each candidate edge e on the shortest path, remove e and test
reachability. Only test edges on the shortest path (not all edges).
```

### 4.2 Deduplication and ranking

Group SPOFs by `shared_asset`, merge affected zones, sum population.
Rank by `affected_population × design_storm_failure_prob`.
Output the top 20 in `results/spofs.json`.

**The synthetic township MUST yield at least:** one `shared_dependency` naming
`S2`, one `colocation` naming `B1`, and one `recovery` SPOF naming a bridge.

## 6. Pre-event optimiser — `analysis/optimize.py`

```python
@dataclass(slots=True)
class Plan:
    budget_inr: float
    interventions: list[str]
    cost_inr: float
    cvar_before: float
    cvar_after: float
    eal_before: float
    eal_after: float
    worst_zone_cvar_after: float
    steps: list[PlanStep]          # the greedy trace = the frontier

@dataclass(slots=True)
class PlanStep:
    intervention_id: str
    cumulative_cost_inr: float
    cvar_after: float
    marginal_cvar_reduction_per_lakh: float
```

### 6.1 Greedy algorithm (default, must be implemented exactly)

```
selected = []
losses   = baseline weighted losses (array of length n)
budget_left = budget

repeat:
  tail_idx = indices of the worst ceil(n * 0.15) losses      # EXTENDED tail
  best = None
  for each candidate c not in selected with cost <= budget_left:
      trial_losses = losses.copy()
      new = run_set_subset(engine, scenarios, Overlay(selected + [c]), tail_idx)
      trial_losses[tail_idx] = [new[i] for i in tail_idx]
      gain = cvar(losses, alpha) - cvar(trial_losses, alpha)
      score = gain / c.cost_inr
      if score > best.score: best = (c, gain, trial_losses)
  if best is None or best.gain <= 0: break
  # Verify: re-simulate ALL scenarios for the chosen set
  losses = run_set(engine, scenarios, Overlay(selected + [best.c])).weighted
  selected.append(best.c); budget_left -= best.c.cost_inr
  record PlanStep
```

**Why the extended tail is safe:** interventions only reduce losses, so a
scenario outside the worst 15% cannot enter the worst 5% as a result. Assert
this in a test; if violated, fall back to full re-simulation.

**Performance guard:** if `len(candidates) × len(tail_idx)` exceeds 50,000
simulations per greedy step, sub-sample candidates to the 40 with the highest
`tail_criticality` of their target asset and record that this happened.

### 6.2 Frontier

```python
def frontier(engine, scenarios, catalogue, max_budget, cfg) -> list[PlanStep]
```
Run the greedy to `max_budget` once; every prefix of `steps` is a plan.
Write `results/frontier.json` with cumulative cost and CVaR at each step.

### 6.3 Equity constraint (optional flag)

`--max-zone-cvar X`: reject any candidate whose selection leaves
`worst_zone_cvar > X`. Report when the constraint binds.

### 6.4 MILP upgrade (optional, behind `--milp`)

Only if `pulp` or `mip` is importable. Formulate Rockafellar–Uryasev CVaR over
precomputed per-scenario effects `Δ[c][i]` (loss reduction of candidate `c` in
scenario `i`, computed independently), then **re-simulate the chosen set** and
report both the MILP estimate and the true value. If they differ by more than
10%, report the discrepancy rather than hiding it.

## 8. Ensemble — `analysis/ensemble.py`

```python
@dataclass(slots=True)
class EnsembleMember:
    id: str                       # "m00".."m19"
    seed: int
    township: Township
    cfg: Config
    perturbations: dict[str, float]   # what was changed, for reporting
```

### 8.1 Generation (`n_members = 20` default)

Member 0 is the unperturbed baseline. For members 1..n-1, perturb:

| What | Distribution |
|---|---|
| `backup_hours` (all assets with > 0) | `× U(0.5, 1.5)` |
| `fuel_hours` | `× U(0.6, 1.4)` |
| `fragility_median_m` | `× LogNormal(0, 0.25)`, clipped to `×[0.6, 1.7]` |
| `water_storage_hours` (zones) | `× U(0.6, 1.5)` |
| `cfg.energy.deenergise_flood_fraction` | `+ U(-0.1, 0.1)` |
| `cfg.comms.handover_capacity_factor` | `× U(0.8, 1.3)` |
| Synthetic links only | 20% of `POWERS` links from feeders are re-pointed to the second-nearest substation |
| Synthetic fibre routes | 30% chance each fibre's `HOSTED_ON` host is removed |

**Only `SYNTHETIC` and `INFERRED` provenance objects may have their topology
perturbed.** `OBSERVED` topology is fixed. Assert this in a test.

### 8.2 Robust optimisation

```python
def robust_plan(members, scenarios_per_member, catalogue, budget) -> RobustPlan
```

- Run the greedy optimiser on every member.
- `selection_frequency[c] = fraction of members selecting c`.
- `RobustPlan.interventions` = chosen by minimax regret:
  for each member's plan `p`, compute its CVaR on every other member;
  `regret(p, m) = cvar(p on m) - cvar(best plan for m on m)`;
  select the `p` minimising `max_m regret(p, m)`.
- Report both the minimax plan and the selection frequencies (the UI shows the
  frequency as a confidence badge).

### 8.3 Value of information

```python
def value_of_information(members, groups, catalogue, budget) -> dict[str, float]
```

For each uncertainty group `g` (`backup_hours`, `fragility`, `water_topology`,
`fibre_hosting`, `operator_thresholds`):

```
VOI(g) = E_m[ cvar(robust_plan on m) ] - E_m[ cvar(best plan for m on m) ]
         restricted to members that differ only in group g
```

Interpretation: how much tail loss we would avoid if we knew `g` exactly.
Report in person-hours and as a percentage of baseline CVaR, ranked.

## 12. N-2 search — `analysis/criticality.py::critical_sets`

```
candidates = top 25 assets by tail_criticality
for each unordered pair (a, b):
    joint = simulate(no-flood, forced_failures=(a,b)).weighted_loss_ph
    synergy = joint - standalone[a] - standalone[b]
rank by synergy desc, keep top 50
```
625 pair simulations × ~20 ms ≈ 13 s. Acceptable without a surrogate.
